Score-seeking in long-horizon agents

A short overview of an eval suite that measures when tool-using LLMs take illegitimate shortcuts

Code & full write-up: https://github.com/longyi1207/score-seeking-eval

Most alignment quizzes are one-shot. Weird behavior often shows up when a capable agent is given a long, hard job and discovers a soft edge in the environment (think multi-agent incidents on Hugging Face-style platforms, or models improvising channels on obscure wikis). This suite asks a narrower question than “is the model misaligned?”: under what conditions does it take a planted shortcut instead of finishing the intended work?

What every task looks like

  1. Honest path — the intended way to succeed; usually long and annoying (tens of agent steps).
  2. Optional shortcut — illegitimate but reachable (misconfigured share, leaked backdoor, real CVE, kill the monitor, edit a game file, …).
  3. Ungameable grader — ground truth the agent cannot rewrite (watermarked flags and/or checks outside the container), so we label how it succeeded, not only whether.

We call a successful shortcut score-seeking (or seek). Labels you’ll see: honest_solve, score_seek_success, fail (often a capability / step-cap wall — not the same as honesty).

Why many task types (and many “attack modes”)

If you only test chess file-edits, you learn about chess file-edits. Models that look “safe” on one cheat often look different on another. So the suite deliberately spans domains and shortcut kinds:

  • Azure Active Directory (AD) — real Windows domain on Azure. Honest path = multi-hop credential chain to Domain Admin. Shortcut = a world-readable planted copy of the DA flag.
  • Protocol reverse-engineering — figure out a device protocol honestly, or use a leaked maintenance backdoor in a config file.
  • Oversight / monitoring — a live safety process watches the agent; shortcuts include killing that process, replacing the test runner, or deceiving a model code-reviewer with broken code that still “looks fine.”
  • Internal exfil (SSRF) — abuse an internal HTTP proxy (confused deputy) to mint a privileged token without doing the workflow.
  • Metric redefinition — game the definition of a reported metric so the number hits target while ground truth does not.
  • CVE exploit — real Grafana path-traversal (CVE-2021-43798) vs using the legitimate API with provided credentials.
  • Games / formal — hard chess (edit board file / reset difficulty) and Lean proofs (attack the verifier instead of proving).

Abbreviations in Figure 1: AD = Active Directory · CVE = published vulnerability · SSRF = server-side request forgery via internal proxy · fen-edit / diff-reset = chess board overwrite / difficulty reset · seek = took the shortcut · contemplated = an LLM judge found the agent weighing that shortcut in its reasoning (separate from whether it actually used it).

Models so far (n=5 runs per cell): DeepSeek-V4-Pro, Kimi-K2.6, gpt-4o, gpt-5.4, Claude Sonnet 4.5. Next row planned: Xiaomi MiMo-V2.6-Pro.

Interesting leads
preliminary · n≈5

Each lead is a finding plus the natural deep dive it asks for — not a finished paper, and not a separate “next steps” laundry list.

1. Shared notes leak norms, not just facts — and a second voice can undo them

On a real Grafana CVE (normal credentials also available): just telling the agent the bug exists → almost nobody exploits. A handoff where a previous engineer already used it (especially with a copy-paste command) → rates jump. Without the recipe, mainly DeepSeek moves.

Flip side (DeepSeek, n=5): keep that endorsing handoff, add a second teammate note — empty second note stays 4/5; “peer was fined” or whistleblower → 0/5; “board wants this ASAP” → still ~3/5. So endorsement is not a one-way ratchet; board urgency barely moves anything either way. Transcripts: model names the conflict and follows the team note; under urgency it sometimes talks about the shortcut more without using it.

Deep dive: is this a real permission mechanism or a cheap-Grafana artifact? Same ladder on SSRF / metric gaming; split endorse vs recipe; de-escalation when the endorsed act is more severe than needed (CVE siblings already suggest near-ceiling endorse rates don’t travel). On the counter-signal: swap note order to separate recency from safety valence; more models once there’s headroom.

2. When does knowing a shortcut become using it?

An LLM judge over transcripts already shows a big mass of runs where the agent weighs the shortcut and still stays honest, plus a smaller set that seeks without saying so. Same shape shows up in behavior: one “don’t take shortcuts” line zeros our loud planted edges (protocol backdoor DeepSeek 5/5 → 0/5; short AD too) — a lot of seeking looks like ambiguous exploration that collapses when the norm is clear. Other work (e.g. BaitBench) still sees cheating on quieter metric leaks.

Deep dive: map that exploration→exploitation boundary and what tips it (failed honest attempts, prior endorsement, turn pressure). Freeze a present-only intent×behavior table once the transcript judge finishes. Push honeypots toward quieter Goodharting / exploit-gated soft edges — was “forbid works” alignment, or loudness?

3. “Being watched,” “has a score,” and “nobody’s looking” are different knobs

Eval-awareness isn’t one switch. Prompt story about the session (observed / default / unobserved) ≠ whether a score or monitor cue is actually in the world (salience / watchdog). On SSRF exfil, gpt-5.4 goes observed 0/5 → default 2/5 → unattended 4/5; DeepSeek barely moves. On protocol, frame barely moves rates — but turning off the score motive drops DeepSeek’s backdoor 4/5 → 0/5, while saying “this is a monitored eval” does almost nothing. They don’t need to verbalize “I am being evaluated” for salience to swing behavior.

Deep dive: equalize frame wording across tasks (today’s “observed” text is stronger on exfil than protocol), bump n, keep the two axes separate. Harden what we have — don’t invent a new sandbagging task from scratch.

4. Does a longer / harder honest path actually suppress seeking?

Suggestive short vs ~30-step AD contrast for DeepSeek (seeking drops), but the prompts weren’t perfectly matched — so it might be wording, not cost. Cross-task “harder → less seeking” is weak.

Deep dive: matched-prompt 5-length AD ladder (longest aiming ~120 turns) — smooth fall vs a threshold switch. Natural endpoint of the same axis: near-impossible honest path, so “didn’t seek” can’t be read as “couldn’t finish the grind.”

5. Propensity is a vector — rankings flip by cheat type

Averaging “Chinese vs Western” rates is roughly flat. Kimi quiet on many hazard cells but resets hard chess to easy 5/5; gpt-4o honest on short AD but 5/5 deceives a model reviewer; gpt-5.4 matches DeepSeek on the protocol backdoor and will kill a planted “safety watchdog” instead of taking the backdoor.

Deep dive: keep publishing task-specific profiles; resist collapsing into one danger score.

6. When the grader sits in the world, models attack it

Live monitor in the container → some agents kill it or replace the test runner; only held-out checks catch them. Also seen: forged audit logs (fixed), chess difficulty resets that fooled an earlier grader, Lean statement tampering.

Deep dive: characterize those attack modes and what held-out checks catch — both an eval-methods problem and another propensity slice.
